# UI/UX 优化方案与分阶段执行记录

## 目标与审查依据

围绕桌宠陪伴、AI 对话、角色管理三个核心场景，保护用户操作成果，统一 UI 风格，改善内容布局和可访问性。
初始审查基于 Vue 组件、状态管理和窗口配置源码；桌面视觉、透明背景、系统缩放与原生窗口行为仍需实机验收。

## 执行约定

- 每阶段独立实施、验证并交用户审查。未经用户明确审查通过，不提交 Git、不进入下一阶段。
- 收到通过意见后，更新本记录，提交该阶段相关文件，再进入下一阶段；不自动推送远端。
- 审查要求修改时，继续在当前阶段修正和复验。
- 提交仅包含本任务变更；发现用户已有改动时保留，不覆盖。
- 每阶段交付列出变更、验证结果、限制和人工验收步骤。

## 阶段 2：删除、保存与失败恢复

状态：用户已审查通过（2026-09-06），授权提交；按用户要求暂停，暂不进入阶段 3。

任务：
- 删除会话、清空历史前明确显示影响；若提供撤销，延迟清理文件检查点。
- 统一未保存状态，覆盖切设置标签、角色编辑返回、关闭窗口，提供保存并离开、放弃更改、继续编辑。
- 配置保存增加进行中、成功、失败反馈，失败保留输入。
- 明确发送接受状态；父组件拒绝发送不丢草稿，网络失败可重试或恢复输入。
- 评估草稿持久化与附件容量、删除会话后的草稿清理。

验收：取消删除不改变数据；未保存更改在所有退出路径均受保护；保存和发送失败可恢复。

本阶段实现：
- 会话删除、历史清空显示名称、消息和文件检查点的清理影响；默认聚焦取消。不增加撤销功能，检查点仍在用户确认后清理。
- API、搜索、语音、角色编辑统一提供离开确认；覆盖标签切换、角色编辑返回、关闭设置窗口。保存失败留在原页，保存中的新输入不会被误标为已保存。
- 新建角色表单增加离开保护；角色保存显示进行中，失败保留编辑内容。
- 语音 Workspace ID 随配置持久化；查询音色使用当前表单配置，不再隐式保存表单。
- 发送等待父组件返回结果；拒绝或网络错误保留原会话的文字与图片，成功或已接受后的主动取消才清理。失败后的已接受用户消息仍保留在历史中，不自动重试或撤销工具操作。
- 已删除会话的内存草稿及时释放，异步读图/发送不会写入其他会话。
- 四种界面语言均补齐确认、未保存及失败文案。

草稿持久化评估：
- 现有单张图片上限 10 MiB、单会话附件总量 20 MiB、最多 4 张；Base64 约增加三分之一体积，不适合直接写入 localStorage。
- 本阶段保留内存草稿，不增加磁盘存储或静默淘汰其他会话草稿；删除会话会释放对应草稿。关闭应用或崩溃后仍不恢复草稿。
- 后续如需要跨重启恢复，应使用独立附件文件、总容量管理与会话删除清理机制，并向用户明确存储行为。

人工审查步骤：
1. 删除会话和清空历史时检查名称与影响；点取消后消息应完整保留。
2. 修改 API/搜索/语音配置后切换标签，分别验证继续编辑、放弃更改、保存并离开。
3. 编辑角色后点击返回、切换设置标签、点击窗口关闭或 Alt+F4，确认更改受保护。
4. 检查保存失败反馈；失败后留在原页，输入保持，可重试。
5. 断网或配置无效时发送文字/图片，确认草稿保留；恢复连接后可手动重试。
6. 切换会话、删除有草稿的会话，确认草稿不串入其他会话。

限制：原生窗口关闭和真实服务故障仍需桌面实机审查；浏览器验收不能替代 Tauri 原生行为验证。角色导入资源沿用已有即时文件导入机制，放弃表单更改不撤回已导入的资源文件。

## 阶段 3：首次引导与设置导航

状态：用户已审查通过（2026-09-06），授权提交并继续下一阶段。

任务：
- 未完成配置时主按钮为继续配置，稍后不等于完成，保留可恢复的配置待办。
- 添加角色、配置 AI 等入口可定位到已有设置窗口的正确标签。
- 区分信息已填写、已保存、连接测试通过，不以字段有效冒充连接成功。
- 设置按使用体验（通用、角色、语音）、连接与能力（AI、搜索、权限）、维护与帮助（隐私、诊断、关于）组织。

验收：零角色首次启动可以完整走通；已有设置窗口时导航准确；状态文案与真实结果一致。

本阶段实现：
- 引导完成语义拆分：两步齐全后主按钮为「开始使用」，点击才写入完成标记；未完成时主按钮为「继续配置」，直接定位第一个未完成步骤（API → 角色），不产生完成标记。
- 「稍后再说」仅写入搁置标记（STORAGE_ONBOARDING_DISMISSED），不再等于完成；被搁置且 API 未配置时，主窗口显示「完成初始配置」待办按钮，可随时重新打开引导。零角色场景仍由现有零角色引导承接，避免双重提示。
- 已有设置窗口时，「去配置 / 去添加 / 添加角色」等入口在聚焦窗口的同时通过 EVENT_SETTINGS_NAVIGATE 事件定位到目标标签；设置窗口侧复用 selectTab，当前标签有未保存更改时先经三选项确认。
- API、搜索页移除仅代表字段有效的「配置可用」徽标：保存后显示「已保存，连接未验证」，连接成功仅来自「测试连接」结果；修改配置后清除过期的测试结果。引导步骤 1 的就绪文案由「已配置」改为「已保存」。
- 设置导航分组：使用体验（通用、角色、语音）、连接与能力（AI、搜索、权限）、维护与帮助（隐私、诊断、关于；开发构建追加 Dev）。
- 新增「权限」页承接原通用页的「自动执行文件修改」「允许 AI 执行本地任务」开关；新增「诊断」页承接原关于页的日志查看入口。
- 四种界面语言同步增删改文案。

边界：
- 跨窗口标签定位依赖 Tauri 事件（emitTo），浏览器预览无法端到端验证，已用单测覆盖设置窗口接收端；实机行为需桌面审查。
- 「完成初始配置」待办按钮在真实桌面数据下出现；浏览器预览因无角色数据走零角色引导路径，按钮被有意抑制。

人工审查步骤：
1. 清空应用数据后首次启动：引导应显示；点「去配置」应打开设置并停在 AI 标签；保存配置后引导步骤 1 显示「已保存」。
2. 配置未完成时点「稍后再说」：引导收起、重启后不再整层弹出；主窗口出现「完成初始配置」按钮，点击可重新打开引导；完成两步并点「开始使用」后待办按钮消失。
3. 引导打开时先手动开一个设置窗口（停在任意标签），再点引导「去添加」：设置窗口应聚焦并切到角色标签；当前标签有未保存更改时应先弹三选项确认。
4. API 页填写有效配置并保存：按钮变「✓ 已保存」且旁现「已保存，连接未验证」；点「测试连接」才出现连接成功/失败；修改任意字段后旧测试结果消失。
5. 检查设置侧栏三组及新增权限、诊断页；原通用页不再有权限开关，关于页不再有日志入口；Dev 仅开发构建显示。
