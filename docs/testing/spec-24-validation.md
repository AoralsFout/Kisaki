## 自动验证方法

在仓库根目录运行：

```powershell
cargo test --manifest-path src-tauri/Cargo.toml --locked --all-targets
cargo clippy --manifest-path src-tauri/Cargo.toml --locked --all-targets -- -D warnings
npm test
npm run build
npx tauri build --no-bundle
```

架构检查是 Rust 测试的一部分，使用语法结构而不是行数或整段源码快照。它针对生产代码检查全局状态、目录兜底与组合根边界，测试模块及真实临时目录 fixture 不作为生产装配点。

## 契约与删除范围核对

- 对照基线的 **53 个 Tauri 命令签名及 53 个注册入口**，仅排除框架注入的状态参数；命令名字、其余参数和返回类型一致。
- 原有 JSON / ZIP 格式与日志 v2 字段由行为测试覆盖。`kisaki-execution-output` 和 TTS Channel 的既有事件契约不变。
- 前端业务源码、Tauri 窗口配置、能力配置、托盘与光标轮询实现不因这次装配改动而重写。
- 重置仍只清理原有角色、日志、会话及检查点备份范围，不扩大到授权记录、凭据或执行输出。

## Windows CI 的测试 fixture 修正

旧的执行撤销测试在 Windows CI 连续两次等待就绪超时，而本机通过。仅将就绪输出从 `Write-Output` 改为 `Console.Out.WriteLine` 加显式刷新后，对照提交 `ee509db` 的三个平台 CI 全部通过。

扩大执行覆盖后，Windows CI 又暴露了测试释放条件对 PowerShell cmdlet 的依赖；加入 `Get-Location` 的诊断还会让阻塞提前到就绪阶段。测试 fixture 因而改用 `Console`、`File.Exists` 和 `Thread.Sleep` 的 .NET API，不依赖被清理环境下的 cmdlet / 模块装载。未放宽超时，未更改生产环境清理、安全规则或执行方式。临时目录探针已删除，失败时的命令与输出诊断保留。该修正的提交 `f7f8f9c` 已通过 [Windows、Linux、macOS 完整 CI](https://github.com/AoralsFout/Kisaki/actions/runs/34687325905)。
