# ADR-0002：时间线投影是模型历史的唯一来源

- 状态：已接受
- 日期：2026-09-22
- 关联：spec #26；实施工单 #58；ADR-0001；`CONTEXT.md` 的「模型历史」与「实时模型上下文」

## 决定

会话时间线的模型协议投影是模型历史的唯一来源。切换会话、重建实时模型上下文和模型配置刷新都直接消费该投影；生产代码不得经由协议快照再解析，也不得从 UI 消息列表重建模型历史。

实时模型上下文只负责当前请求期间的内存状态：追加本轮消息、执行预算裁剪、维护滚动摘要，并把新生成的摘要事实写回会话时间线。设置页等检查能力可以读取实时上下文或时间线投影，但不改变模型历史来源。

会话持久化格式保持现有 v2 文档不变。

## 背景

- `ConversationSessionSnapshot.timeline` 同时承载用户消息、工具交换和助手提交事实；`SessionAggregate.projectModelContext()` 已能直接生成模型协议消息，并与实时上下文的追加结果保持等价。
- 旧恢复路径先把 `ChatContext` 转成脱敏协议快照，再在新上下文中解析；图片因不进入快照，还需要从 UI transcript 按用户消息顺序手工补配。这条路径拥有第二份历史形状和额外的配对规则。
- 模型配置刷新与会话切换现在已经可以直接调用 `loadModelProjection()`，因此协议快照转换、UI 重放和手工图片补配不再有生产用途。
- 设置页检查器需要的是受限的检查视图，仍可从实时上下文或时间线模型投影生成，不需要恢复快照。

## 被否的替代方案

### 通过协议快照恢复实时上下文

快照可以脱敏并跨版本拒绝，但它把实时状态重新变成一份需要维护的协议格式。它丢失模型历史中不应丢失的结构（尤其是图片），还要求恢复端再次解析工具配对和正文，形成时间线投影 → 快照 → 解析的往返。因此否决。

### 从 UI 消息列表重放模型历史

UI transcript 是展示层自有状态，只覆盖展示文案，不能表达完整的 assistant/tool 协议交换、工具参数、回执和滚动摘要。用它重建会让展示层重新成为模型历史的 Owner，也会引入图片按位置配对的脆弱规则。因此否决。

### 让实时上下文成为持久化历史的第二个 Owner

实时上下文适合预算裁剪和请求内优化，但它会随模型配置、当前角色和运行时工具定义变化。把它持久化或作为恢复真相会重新引入格式迁移、裁剪结果污染历史和多 Owner 不一致。因此否决。

## 后果

- 会话切换和模型配置刷新只需装载时间线模型投影，历史结构、工具交换和图片由同一份会话事实提供。
- 生产代码少一条协议快照转换链，删除了 UI 重放与手工图片补配；结构化架构守卫会阻止这两类路径重新进入。
- 实时上下文必须保留自己的预算裁剪与滚动摘要逻辑，并在摘要发生变化时异步写回会话事实；写回失败不能破坏当前请求，但会产生可观测的持久化错误。
- 设置页检查能力仍需维护图片元数据脱敏和摘要展示逻辑；这些是检查视图的安全责任，不是模型历史恢复机制。
- 代价是每次上下文重建都要从时间线重新投影，并由当前模型配置重新进行预算裁剪；这会增加一次纯内存计算，但避免了持久化格式和恢复分支的长期维护成本。
- 该决定不改变 v2 会话文档、时间线事件、检查点、角色外观或工具批准语义。若未来需要跨设备同步或独立的历史查询格式，应另立 ADR，而不是把协议快照恢复路径带回实时上下文。
